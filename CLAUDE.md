# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Docker is the preferred way to *run* the app (see `Dockerfile` / `docker-compose.yml`); `uv` is for local development (tests, lint, editing with reload). The app requires a one-time Authentik bootstrap first — see README.md's "Authentication setup" section — and fails to start without `SESSION_SECRET_KEY`/`AUTHENTIK_*` env vars set.

```bash
HOST_UID=$(id -u) HOST_GID=$(id -g) docker compose up -d --build   # build + run (preferred)
docker compose logs -f                                             # tail logs
docker compose down                                                 # stop and remove

uv sync                    # install/update dependencies
uv run fastapi dev         # dev server with reload (entrypoint from [tool.fastapi] in pyproject.toml)
uv run fastapi run         # production server, native
uv run playwright install chromium   # one-time, for the browser-driven frontend tests
uv run pytest              # run all tests
uv run pytest -m "not frontend"      # skip the browser layer
uv run pytest app/tests/test_frontend.py   # browser layer only (no model load)
uv run pytest app/tests/test_scoring.py::test_identical_text_scores_100   # single test
uv run ruff check .        # lint
uv run ruff format .       # format
```

No separate build step — the frontend is plain static files served directly by FastAPI.

## Architecture

This is a local FastAPI app: record yourself saying an English phrase, get a phoneme-level pronunciation score. It requires login (OIDC via Authentik) and scopes attempt history/stats per authenticated user.

**Scoring pipeline** (the core of the app, spans `app/ml.py`, `app/scoring.py`, `app/routers/attempts.py`): uploaded audio → `faster-whisper` transcribes it to text → `app/scoring.py` normalizes both the target phrase and the transcript into word lists → `g2p_en` converts each word *individually* to ARPAbet phonemes (called per-word, not per-sentence, to avoid the `" "` separator tokens `g2p_en` inserts between words on sentence input) → `difflib.SequenceMatcher` aligns reference/hypothesis word lists (equal/replace/delete/insert opcodes map to correct/mispronounced/missing/extra) → phoneme-level edit distance per aligned word pair produces a 0–1 word score → the overall 0–100 score is the mean word score across all non-`extra` words.

**Model lifecycle**: `WhisperModel` and `G2p` are both expensive to load and are instantiated exactly once, in `app/main.py`'s lifespan, and stashed on `app.state`. Request handlers reach them via the `WhisperModelDep`/`G2pDep` dependency aliases in `app/ml.py` — never re-instantiated per request. The Whisper model defaults to `small.en` / `compute_type="int8"` / `device="cpu"`, overridable via the `WHISPER_MODEL_SIZE` / `WHISPER_COMPUTE_TYPE` env vars.

**Self-contained runtime data**: `app/config.py` computes every runtime path (SQLite DB, saved recordings, Whisper model cache, nltk data) under `data/`, and sets the `NLTK_DATA` env var *before nltk is ever imported anywhere in the process* — order matters here, since nltk's `default_download_dir()` only picks a directory that already exists on disk at first use, and always falls back to `~/nltk_data` otherwise. The whole `data/` root is overridable via `PRONUNCIATION_COACH_DATA_DIR` (this is how tests get an isolated runtime).

**nltk is pinned `<3.9`**: `g2p_en`'s own downloader requests the legacy `averaged_perceptron_tagger` resource, but nltk ≥3.9 looks up `averaged_perceptron_tagger_eng` by default — a mismatch that surfaces as a `LookupError` on first real use, not at import time. `ensure_nltk_data()` in `app/ml.py` defensively tries both resource names as a second line of defense.

**Frontend**: plain HTML/CSS/JS in `frontend/`, no bundler. Served via `router.frontend("/", directory=...)` on a dedicated `APIRouter(dependencies=[Depends(require_web_session)])` in `app/main.py`, mounted *after* the API routers so it never shadows `/api/*` — a low-priority static route that only matches once no other route does.

**Authentication** (`app/auth.py`, `app/routers/auth.py`): backend-driven OIDC Authorization Code flow against Authentik via `authlib`'s Starlette `OAuth` client — `/auth/login` redirects to Authentik, `/auth/callback` exchanges the code, upserts a local `User` row keyed by the OIDC `sub` claim, and stores `user_id` in a signed session cookie (Starlette's `SessionMiddleware`; tokens never reach the browser JS). **Logout is RP-initiated, not local-only**: `/auth/logout` clears the local session and then redirects to Authentik's `end_session_endpoint` (discovered from the OIDC metadata, never hardcoded) with `post_logout_redirect_uri` and an `id_token_hint` — the `id_token` is stashed in the session at callback purely for that hint. Clearing only our own cookie is *not* enough: Authentik keeps its own session, so the subsequent redirect to `/auth/login` gets silently re-authorized and drops the user straight back into a logged-in app, making Logout look like a no-op. This also depends on the Authentik provider using `default-invalidation-flow`, **not** `default-provider-invalidation-flow` — the latter ships with no stages bound to it and ends only the per-application session (see `authentik-blueprints/pronunciation-coach.yaml`). If the metadata fetch fails, logout degrades to a plain redirect to `/` rather than 500ing. Two dependencies share one resolver: `get_current_user` (401 JSON, used by `/api/*` and testable via `app.dependency_overrides`) and `require_web_session` (raises `WebAuthRequired`, caught by an `app.add_exception_handler` that 302s to `/auth/login?next=...`, used by the frontend router). **Key fact this relies on**: FastAPI's `router.frontend()` genuinely runs router-level `dependencies=[...]` through the normal dependency-injection machinery before serving a matched static file (`_FrontendRouteGroup.handle()` in `fastapi/routing.py`) — confirmed by reading the installed FastAPI source, not assumed — which is why gating the whole app needs no hand-rolled ASGI middleware. `/docs`/`/redoc`/`/openapi.json` are unaffected (they're default routes on `app`, never part of the frontend router), so the Dockerfile healthcheck (`GET /docs`) needs no auth.

**Data model** (`app/models.py`): `Phrase` (unique `text`, `difficulty`, `category`), `User` (`sub` unique/indexed, `email`), `Attempt` (FK to `phrase` and `user`, `transcript`, `score`, `word_feedback` stored as a JSON column), and `UserPreference` (one row per user — `user_id` FK is `unique`, so the upsert in `app/routers/preferences.py` can query by user and never has to disambiguate duplicates).

**User preferences** (`app/routers/preferences.py`, `frontend/app.js`): `GET`/`PUT /api/me/preferences` read and store the difficulty/category filter selection. `PUT` is a **full replacement** — an omitted field is stored as "no filter", not left alone — which matches how the frontend always sends both selects, and `""` (what an HTML `<select>`'s "Any" option submits) is normalized to `NULL` on write so it can't become a category no phrase matches. `GET` for a user who has never chosen anything returns the same `{difficulty: null, category: null}` shape as one who explicitly chose "Any", so the frontend needs no special case. The category filter is fed by `GET /api/phrases/categories` (distinct non-null categories, sorted). Two ordering constraints in `app.js`'s `init()`, both load-bearing: categories must be fetched *before* preferences (a saved category can only be selected once its `<option>` exists — `hasOption()` guards the case where a saved value is no longer offered at all, which would otherwise silently select nothing), and preferences before the first `loadRandomPhrase()` (otherwise the opening phrase ignores the restored filters and visibly swaps out). Every one of these fetches degrades silently to the unfiltered default rather than blocking startup. `app/seed_data.py` seeds 133 built-in phrases (20 categories × 3 difficulties, grouped in the file by category) idempotently on every startup, keyed off the unique `text` column. **Because the idempotency key is `text`, inserting isn't enough**: editing a seeded phrase's `category`/`difficulty` would never reach an existing DB, so `seed_phrases()` also reconciles drifted rows back to the seed list — that's what made the `technology` → `information-technology` rename actually apply instead of leaving both slugs in the dropdown. `rename_technology_preferences()` does the same for a stored `UserPreference` and is explicitly a stopgap until Alembic. Category slugs are lowercase-hyphenated and reach the UI as `option.value`; `categoryLabel()` in `app.js` derives the display text (sentence case), so there's no slug → label map to maintain. (`UserPreference` is a *new table*, so `create_all()` does pick it up on an existing local DB — unlike a new column such as `Attempt.user_id`.) **No migration tooling yet** (`docs/SPEC.md` has a planned Postgres+Alembic migration) — `SQLModel.metadata.create_all()` only creates missing tables, so adding `Attempt.user_id` doesn't backfill an existing local `data/pronunciation_coach.db`; delete it to pick up the new schema.

**Docker**: `docker-compose.yml` bind-mounts `./data:/app/data`, so the SQLite DB and downloaded Whisper/nltk caches are shared between Docker and native runs and survive container rebuilds. The container runs as `${HOST_UID}:${HOST_GID}` (defaulting to 1000:1000) rather than root, specifically so files written into that bind mount are owned by the host user instead of `root` — set `HOST_UID`/`HOST_GID` (e.g. via a gitignored `.env`) to your actual `id -u`/`id -g` if they differ from 1000.

**Test isolation** (`app/tests/conftest.py`): sets `PRONUNCIATION_COACH_DATA_DIR` to a fresh temp dir, plus dummy `SESSION_SECRET_KEY`/`AUTHENTIK_*` values (required, no-default config — see Authentication above), as top-level module code — this must run before `app.config` (and therefore `app.main`) is imported anywhere, including by other test files, which is why it happens before any other import in the file. The session-scoped `client` fixture then runs the app's real lifespan via `with TestClient(app)`, creates one real `User` row, and overrides `get_current_user` via `app.dependency_overrides` to return it — `authlib` only fetches OIDC `.well-known` metadata lazily on first `authorize_redirect`/`authorize_access_token` call (confirmed by reading the installed `authlib` source), so this never touches a real Authentik instance. Tests needing a *different* user (e.g. proving per-user scoping in `test_auth.py`) temporarily swap the override and restore it in a `finally` block.

**Frontend tests** (`app/tests/test_frontend.py`, marked `frontend`): headless Chromium via `pytest-playwright`, driving the real shipped `frontend/` files. They deliberately **do not start the FastAPI app** — a bare `ThreadingHTTPServer` (the `frontend_server` fixture) serves `frontend/`, and the `api` fixture intercepts every `/api/*` call in the browser with canned responses. That keeps the whole Whisper/G2p model load out of this file, so it runs in ~15s versus ~40s for anything touching the `client` fixture. Two things worth knowing before editing it: (1) the interception is **one** `page.route("**/api/**", ...)` dispatching on path/method, not one route per endpoint, because Playwright matches routes in *reverse* registration order and `**/api/attempts/stats` vs `**/api/attempts/?limit=20` would otherwise shadow each other; (2) `conftest.py` overrides `browser_type_launch_args` to add `--use-fake-device-for-media-stream`/`--use-fake-ui-for-media-stream`, which is what lets the tests exercise the genuine `getUserMedia` + `MediaRecorder` path instead of stubbing it — only the mic-permission-denied test injects a stub, via `page.add_init_script`. Note that `loadHistory`/`loadStats` in `app.js` have no `res.ok` check, so their "Could not load…" fallbacks are only reachable via a *failed* request or an unparseable body, never a 500 with valid JSON — hence the `network_error()`/`malformed_json()` helpers. Server-side frontend wiring (auth gating on `/`, static assets served, and a contract test asserting every `getElementById` in `app.js` has a matching `id` in `index.html`) lives in `test_auth.py` instead, since it needs the real app but no browser.
